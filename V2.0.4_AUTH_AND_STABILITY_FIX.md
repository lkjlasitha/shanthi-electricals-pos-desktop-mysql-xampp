# Version 2.0.4 — authentication and stability fix

## Login repair

The observed desktop flow returned HTTP 200 for `/api/auth/login`, navigated to
the POS, and then returned HTTP 401 for every protected bootstrap request. The
new flow fixes and verifies the complete chain:

1. Successful credentials return a JWT whose subject is the stable MongoDB
   document ID.
2. The browser stores the token in memory and local storage.
3. `/api/auth/me` validates the fresh token before the POS screen mounts.
4. Protected POS requests then use that same verified bearer token.

Older numeric-ID-only JWTs remain accepted until they expire. Startup migration
also repairs MongoDB documents created without their public numeric `id`.

## Failure isolation and crash resistance

- Invalid/expired tokens, invalid users, and database query failures are now
  handled separately instead of all becoming an unexplained HTTP 401.
- Database failures pass to the central API handler and are logged correctly.
- React render failures remain contained by the application error boundary.
- Electron detects unresponsive or crashed renderer processes and offers reload.
- Desktop logs rotate at 5 MB and log-stream failures cannot terminate the app.
- MongoDB transactions continue protecting multi-document sales, purchase,
  return, payment, and stock operations from partial writes.
