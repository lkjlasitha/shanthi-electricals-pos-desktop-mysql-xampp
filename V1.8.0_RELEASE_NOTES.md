# Shanthi Electricals POS v1.8.0

## Product stock editing

- The product edit form now shows every warehouse quantity.
- A stock change requires a reason and creates a normal stock-adjustment document instead of silently overwriting inventory.
- Quantity changes are applied inside the same database transaction as the product edit.
- Only users with `stock.manage` can change opening or existing stock.
- Stock adjustment and transfer records now retain the user who created them.

## Supplier bill and goods-receipt pipeline

- Record the supplier's invoice number, bill date, due date, payment reference and notes.
- Supplier records now have default payment terms in days.
- Save a bill as received immediately or as ordered/bill-only for later delivery.
- Receive an order in one or more partial deliveries. Only the quantities actually received increase stock.
- Duplicate and excessive receipt quantities are rejected while the purchase and line rows are locked.
- Existing v1.7 purchases are migrated as fully received so stock and return history remain correct.

## Accounts payable and partial payments

- Initial bills can be paid, partially paid or unpaid.
- Additional supplier payments have their own date, method, reference, note and user audit row.
- Period, supplier, payment, receiving-status and reference filters are available on the supplier-bills screen.
- The screen and dashboard show outstanding and overdue supplier bills.
- Supplier returns reduce both warehouse stock and the bill payable. Overpayments after a return are shown as supplier credit/refund due.
- Purchase reports include paid, return-credit, net-purchase and outstanding totals.

## Reliability and data-integrity fixes

- Purchase creation, receipt, payment, supplier return, transfer and adjustment operations are transactional.
- Double-submit guards were added to product, purchase, transfer, adjustment and reusable CRUD forms.
- Product IDs, warehouse IDs, dates, quantities, discounts, tax values and payment amounts receive server-side validation.
- Transfers and adjustments reject duplicate products, invalid references, negative/NaN values and insufficient stock.
- Malformed/oversized API bodies, database disconnects, lock timeouts and deadlocks now return actionable responses.
- Invalid pagination no longer reaches Sequelize as `NaN`.
- User creation/update now normalizes email addresses, enforces eight-character passwords, validates references and prevents deleting/deactivating the signed-in account.
- Older v1.7 Excel backups remain restorable; the new supplier-payment table and derived purchase fields are rebuilt after restore.

## Database upgrade

The normal desktop startup runs the additive migration automatically. It:

- adds supplier invoice, due-date, receipt, return-credit and payment fields;
- creates `purchase_payments`;
- widens the old purchase status enum;
- backfills existing received quantities, due dates, return credits and initial payment rows; and
- verifies the new critical columns.

Make a full Excel backup before installing any application update. Browser-development users can run:

```powershell
npm install
npm run db:migrate
npm run db:doctor
npm run verify
```
