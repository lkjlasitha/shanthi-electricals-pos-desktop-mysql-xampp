# Version 2.0.2 — MongoDB connection and diagnostics fix

## What was fixed

- MongoDB settings are now loaded by absolute path, independent of the folder from which `npm` or Node starts the backend.
- Both `backend/.env` and the project-root `.env` are supported. `backend/.env` wins when both define the same setting; an OS or Electron environment variable wins over both.
- MongoDB checks report the selected configuration source and a credential-free server/database target.
- Driver details for DNS/SRV, TLS, authentication, refused connections, timeouts, and invalid URI syntax are retained and converted into actionable messages.
- URI values and credentials are redacted from diagnostic output.
- An unquoted `#`, whitespace, placeholders, illegal SRV host/port combinations, and invalid percent encoding are detected.
- The parsed database name is explicitly supplied to Mongoose, including when the URI does not include a database path.
- Electron first-run MongoDB validation uses the same parser and error formatter as the backend.
- Root and backend `.env` files are excluded from source control and Electron packaging.

## Recommended `.env` format

```dotenv
MONGODB_URI="mongodb+srv://POS_USER:ENCODED_PASSWORD@CLUSTER/electro_pos?retryWrites=true&w=majority"
```

Percent-encode reserved characters inside credentials. Common examples are `@` → `%40`, `#` → `%23`, `:` → `%3A`, and `/` → `%2F`.

Run `npm run db:check` first. It now identifies whether the URI came from the process environment, `backend/.env`, the project-root `.env`, or the local default, then prints the actual safe failure category and underlying driver detail.
